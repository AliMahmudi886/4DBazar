# ممیزی هسته UX موبایل 4D

## شواهد این فاز

- بازار روی صفحه کوچک به‌جای تمرکز روی feed، فضای زیادی را به hero و پنل‌های فیلتر می‌دهد؛ کارت‌ها باید محدود، خوانا و یک‌ستونه/دوستونه واقعی باشند.
- فرم ثبت آگهی در یک صفحه بلند است و انتخاب شهر/دسته با chip افقی، روی موبایل clipping و اسکرول مبهم ایجاد می‌کند.
- bottom navigation در میانه‌ی flow ثبت آگهی مزاحم است و باید هنگام ثبت، مخفی باشد.
- پروفایل هم‌زمان dashboard و فرم ویرایش است؛ چهار تب فشرده و دو status card بزرگ، hierarchy موبایل را ضعیف می‌کند.

## Root causeهای فنی

1. `MarketScreen` چند پنل سنگین را پیش از feed رندر می‌کند و `FlatList` دو ستونه را بدون سیاست صریح اندازه‌گذاری کارت استفاده می‌کند.
2. `CreateScreen` انتخاب‌های اصلی را در `ScrollView` افقی نگه می‌دارد؛ این الگو برای تعداد متغیر شهر/دسته در عرض ۳۶۰ تا ۴۳۰ مناسب نیست.
3. `TabsShell` bottom navigation را برای `create` نیز نمایش می‌دهد.
4. `ProfileScreenV6` چهار تب را در یک ردیف ثابت و فرم حساب را در root نمایش می‌دهد.

## اولویت اصلاح

- P0: خوانایی و اندازه‌گذاری feed، stateهای loading/error/empty، حذف nav از ثبت آگهی.
- P1: انتخاب‌های شهر/دسته بدون clipping، فاصله‌ی امن پایین، تب‌های قابل اسکرول و status فشرده.
- P2: تبدیل کامل فرم به wizard چندمرحله‌ای و زیرصفحه‌های پروفایل؛ این بخش نیازمند بازطراحی بزرگ‌تر و smoke واقعی دستگاه است.

## محدودیت تست

API تولیدی از همین سیستم برای health، readiness، categories، feed و captcha پاسخ ۲۰۰ می‌دهد. دستگاه فیزیکی در این محیط متصل نیست؛ بنابراین تست نهایی لمس و اندازه‌های واقعی گوشی باید پس از نصب APK انجام شود.
