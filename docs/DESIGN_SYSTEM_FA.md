# سیستم طراحی محصول 4D

این سند مرجع مشترک Web و Mobile است. هر صفحه یا feature تازه باید قبل از پیاده‌سازی با این قواعد تطبیق داده شود.

## شخصیت محصول

4D یک بازار محلی عملیاتی است؛ ظاهر آن باید قابل اعتماد، سریع، انسانی و کم‌اصطکاک باشد. محصول نباید شبیه landing page تبلیغاتی، داشبورد سازمانی خشک یا کپی مستقیم بازارهای عمومی باشد.

اصول اصلی:

- آگهی و اقدام کاربر در نمای اول دیده شود.
- هر صفحه یک اقدام اصلی واضح داشته باشد.
- اعتماد با رفتار واقعی محصول، وضعیت‌ها و متن دقیق ساخته شود؛ نه با badgeهای تزئینی.
- RTL باید در ترتیب محتوا، جهت حرکت، چت و کنترل‌های تعاملی واقعاً تست شود.
- انیمیشن فقط برای ورود آرام، بازخورد لمس/hover و تغییر state است.

- نسبت کنتراست متن و کنترل با Axe در quality gate سنجیده شود.

## تایپوگرافی

- Web: `Segoe UI`, سپس `Tahoma` و `Arial`.
- Mobile: فونت سیستم تا زمانی که فونت فارسی رسمی با بررسی اندازه APK تصویب شود.
- عنوان صفحه موبایل ۲۴ تا ۲۶، عنوان کارت ۱۴ تا ۱۷ و metadata حداقل ۱۱ است.
- اندازه فونت با عرض viewport به‌صورت مستقیم scale نشود.
- letter spacing منفی ممنوع است؛ فقط OTP می‌تواند فاصله مثبت کنترل‌شده داشته باشد.

## هندسه و فاصله

- radius استاندارد کارت و کنترل: `8px`.
- pill فقط برای badge، status و count مجاز است.
- فاصله پایه: ۴، ۸، ۱۲، ۱۶، ۲۴ و ۳۲.
- دکمه لمسی حداقل ۴۴ در Web و ۴۶ در Mobile باشد.
- card داخل card ممنوع است؛ بخش‌های صفحه band یا layout بدون قاب هستند.
- تصاویر آگهی نسبت پایدار و `object-fit: cover` دارند تا layout جابه‌جا نشود.

## الگوهای Web

- Desktop بازار: ستون فیلتر، feed مرکزی و ستون ثبت آگهی.
- Tablet: ثبت آگهی به ردیف مستقل منتقل می‌شود.
- Mobile: فیلتر پیشرفته ابتدا بسته است، feed جلوتر می‌آید و navigation اصلی پایین viewport ثابت می‌شود.
- جستجو همیشه نزدیک ابتدای صفحه و دسته‌ها به‌صورت نوار افقی قابل اسکن هستند.
- hero بازار یک band فشرده محصولی است؛ نباید محتوای واقعی را زیر fold ببرد.

## الگوهای Mobile

- navigation پایین شامل بازار، ثبت آگهی، گفتگو و پروفایل است؛ ثبت آگهی accent اصلی دارد.
- بازار با جستجو، دسته‌های افقی و کارت‌های تصویری دو ستونه نمایش داده می‌شود.
- فرم‌ها label آشکار، پیام خطای نزدیک و حالت disabled قابل تشخیص دارند.
- پیام خود کاربر در سمت راست و پیام طرف مقابل در سمت چپ نمایش داده می‌شود.
- OTP از Autofill استاندارد سیستم‌عامل استفاده می‌کند؛ مجوز خواندن کامل SMS مجاز نیست.
- مختصات drag کپچا فیزیکی است و باید روی runtime RTL گوشی تست شود.

## Stateها

هر جریان داده‌ای باید این چهار حالت را داشته باشد:

1. Loading با skeleton یا indicator متناسب.
2. Empty با توضیح کوتاه و اقدام بعدی.
3. Error با متن قابل فهم و retry.
4. Success با بازخورد مشخص و بدون موفقیت ساختگی.

## Motion و Accessibility

- ورود surface حداکثر ۴۲۰ms و hover/press حداکثر ۱۸۰ms.
- `prefers-reduced-motion` در Web و accessibility label/state در کنترل‌های Mobile الزامی است.
- icon تنها باید label قابل دسترس داشته باشد.
- focus ring حذف نشود.
- متن بلند فارسی، zoom و viewportهای ۳۹۰، ۷۶۸ و ۱۴۴۰ باید بدون overlap و overflow پاس شوند.

## کنترل کیفیت

پس از هر تغییر بصری مهم:

```powershell
npm run check
npm run build -w @four-d/web
npm run qa:quality -w @four-d/web
cd apps/mobile
npx expo export --platform android --clear
```

اسکرین‌شات‌های مرجع Web در `qa/quality` ذخیره می‌شوند. تغییر native فقط پس از ساخت preview APK و نصب روی گوشی واقعی نهایی محسوب می‌شود.
