# گزارش Development Sprint 105: تجربه وب حمل‌ونقل محلی

تاریخ: ۱۴۰۵/۰۶/۰۳

## هدف

ارائه‌ی یک نقطه‌ی ورود حرفه‌ای و مستقل برای حمل‌ونقل محلی در کنار باکس ثبت آگهی/خدمت، بدون مخلوط‌کردن فرم سفر با فرم عمومی آگهی.

## خروجی‌های تکمیل‌شده

- باکس مستقل حمل‌ونقل محلی در ستون شروع انتشار وب اضافه شد.
- حالت‌های «پیشنهاد مسیر» و «درخواست مسیر» از هم تفکیک شدند.
- فرم اختصاصی سفر شامل عنوان، توضیح، شهر، مبدأ، مقصد، تاریخ، بازه‌ی زمانی، نوع وسیله، ظرفیت/تعداد مسافر و قیمت اضافه شد.
- جست‌وجوی مسیر از همان باکس با endpoint قطعی `/api/v1/transport/search` متصل شد.
- فیلترهای انتخابی مبدأ، مقصد و نوع مسیر اضافه شدند؛ انتخاب‌گرها جست‌وجوپذیرند و فهرست شلوغ را به چند گزینه‌ی قابل اسکن محدود می‌کنند.
- نتایج جست‌وجو خلاصه، قابل اسکن و شامل مسیر، زمان، ظرفیت و قیمت هستند.
- modal مستقل با بستن از طریق کلیک بیرون و کلید Escape پیاده‌سازی شد.
- layout در موبایل به تک‌ستونه تبدیل شد و دکمه‌ها/جست‌وجو از عرض صفحه خارج نمی‌شوند.
- فهرست شهرها و روستاهای موجود برای مبدأ و مقصد در datalist فرم در دسترس است.

## اعتبارسنجی

- `npm run check` موفق.
- `npm run build -- --ignore-scripts` موفق.
- `npm test` موفق: ۵۳ تست API و ۱ تست shared.

## موارد باز و deferred

- migration و smoke نوشتنی روی cPanel باید با داده‌ی واقعی مقصد انجام شود.
- اتصال فرم حمل‌ونقل موبایل در increment بعدی انجام می‌شود.
- استخراج intent با AI بعد از تثبیت تجربه‌ی deterministic و قرارداد API انجام می‌شود.
- رزرو، پرداخت، ردیابی زنده، expiry خودکار و ظرفیت تراکنشی خارج از MVP باقی می‌مانند.
