# گزارش Development Sprint 120 — قرارداد Auth و نشست

## هدف

یکسان‌سازی خطاهای احراز هویت بین API، وب و موبایل و جلوگیری از نمایش خطای اتصال برای خطاهای واقعی رمز، OTP یا شماره موبایل.

## تغییرات واقعی

- `ApiErrorCode` مشترک کدهای `invalid_phone`، `invalid_otp` و `invalid_credentials` را پشتیبانی می‌کند.
- API برای شماره نامعتبر، OTP نامعتبر/منقضی و رمز اشتباه کد دقیق برمی‌گرداند؛ status codeهای قبلی حفظ شده‌اند.
- وب برای ورود با رمز، خطاهای credential، rate limit و اختلال سرویس را جداگانه و فارسی نمایش می‌دهد.
- موبایل کدهای جدید را به پیام کاربرپسند نگاشت می‌کند و آن‌ها را با خطای شبکه اشتباه نمی‌گیرد.
- `/api/v1/me` شماره تلفن حساب صاحب نشست را نیز برمی‌گرداند تا هویت حساب در کلاینت‌ها قابل نمایش و همسان‌سازی باشد؛ شماره کاربران دیگر هرگز در این پاسخ قرار نمی‌گیرد.
- تست‌های API برای قرارداد کدهای جدید اضافه شد.
