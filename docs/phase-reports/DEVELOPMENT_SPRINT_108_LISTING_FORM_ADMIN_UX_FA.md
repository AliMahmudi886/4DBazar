# گزارش Development Sprint 108: اصلاح آگهی، رسانه و پنل ادمین

## هدف

رفع خطاهای عملیاتی ثبت/ویرایش/حذف آگهی و ساده‌سازی فرم قیمت، رسانه و پنل بررسی ادمین.

## خروجی

- ویرایش آگهی اکنون رسانه‌های قبلی را نگه می‌دارد و رسانه‌های جدید را با `media_asset_ids` به همان آگهی متصل می‌کند.
- حذف آگهی در API خطای مالکیت یا وضعیت سرویس را به شکل قابل تشخیص برمی‌گرداند و پیام UI دیگر خطای مبهم نشان نمی‌دهد.
- ورودی فایل بعد از هر انتخاب reset می‌شود تا انتخاب دوباره همان عکس نیز ممکن باشد.
- نوع قیمت آگهی از مبلغ استنتاج می‌شود: مبلغ مثبت یعنی ثابت و نبودن مبلغ یعنی توافقی؛ selector اضافی از فرم آگهی حذف شد.
- دسته‌بندی به ابتدای فرم آمد تا metadata اختصاصی بر اساس دسته انتخاب‌شده ساخته شود.
- صف گزارش‌ها و پشتیبانی ادمین به disclosureهای بسته‌شونده تبدیل شدند تا صفحه با لیست‌های باز اشباع نشود.
- فرم ویرایش از پروفایل همان composer موجود را باز می‌کند و به صفحه بازار منتقل نمی‌شود.

## اعتبارسنجی

- `npm run check` سبز.
- `npm run build` سبز.
- `npm test`: تعداد ۵۴ تست، همگی موفق.

## انتشار

برای مقصد cPanel باید build جدید API و وب هر دو منتشر و سرویس Node restart شود. این increment migration جدیدی نیاز ندارد؛ رسانه‌های چندگانه از جداول موجود استفاده می‌کنند.

## موارد باز

- smoke نوشتن/ویرایش/حذف روی cPanel پس از آپلود release باید انجام شود.
- فرم حمل‌ونقل عمداً selector قیمت مستقل خود را حفظ کرده و منطق آن با آگهی معمولی یکی نیست.

## اصلاحات تکمیلی رسانه و چرخه عمر آگهی، 2026-08-24

- رسانه کارت آگهی ارتفاع ثابت و واکنش‌گرا دارد تا تصاویر با نسبت‌های مختلف layout را جابه‌جا نکنند.
- پنل ادمین در کارت صف و پنجره جزئیات، گالری تصویر و ویدیو را نمایش می‌دهد.
- مهلت ویرایش ۲۴ ساعت در repository/API enforce شده و UI نیز پیش از بازکردن فرم بازخورد واضح می‌دهد.
- حذف مالک با `RETURNING` نتیجه‌ی update را بررسی می‌کند تا حذف ناموفق به‌عنوان موفق گزارش نشود.
- `npm run check`، `npm run build` و `npm test` محلی سبز هستند؛ این increment migration جدیدی ندارد.

## موارد باز پس از این increment

- آپلود جفت ZIP جدید روی cPanel و Restart App.
- smoke واقعی حذف، ویرایش داخل/خارج بازه ۲۴ ساعت و نمایش رسانه در پنل ادمین روی مقصد.
- بررسی محیطی خطای HTTP 500 حذف در صورت استفاده از release قدیمی یا schema ناسازگار.

## Hotfix پس از smoke محلی، 2026-08-24

- کادر انتخاب تصویر از state گالری جدا شد؛ پس از آپلود، picker به حالت خالی برمی‌گردد و رسانه فقط در نوار گالری پایین نمایش داده می‌شود.
- ویرایش آگهی در workspace پروفایل به‌صورت modal مستقل باقی می‌ماند و دیگر با تغییر مسیر به بازار، context پروفایل را از دست نمی‌دهد.
- خطای حذف آگهی در وب، متن خطای JSON API را نیز نمایش می‌دهد تا خطای مالکیت/وضعیت سرویس از خطای عمومی قابل تشخیص باشد.
- `check`، `build` و `test` پس از hotfix دوباره سبز شدند؛ انتشار cPanel جدید باید هر دو ZIP وب و API را شامل شود و پس از آن Restart App انجام شود.

## Hotfix guest boot، 2026-08-24

- پاسخ‌های endpointهای خصوصی اکنون پیش از parse شدن با `response.ok` بررسی می‌شوند؛ بنابراین پاسخ خطای `401` به‌عنوان داده‌ی معتبر تنظیمات تحلیل خوانده نمی‌شود.
- نشست قدیمی در صورت دریافت `HTTP 401` از `localStorage` حذف می‌شود و UI بدون نیاز به پاک‌سازی دستی به حالت مهمان برمی‌گردد.
- `npm run check`، `npm run build` و `npm test` محلی موفق شدند: ۵۳ تست API و ۱ تست shared بدون خطا.
- برای انتشار، ساخت جفت ZIP جدید و Restart App در cPanel لازم است؛ migration جدیدی برای این hotfix نیاز نیست.
- گیت bundle با سقف کل ۶۸۰KB نگه داشته شد؛ سقف chunk مستقل ۴۸۰KB بدون تغییر باقی مانده است تا افزایش حجم routeها کنترل‌شده بماند.
- override قدیمی ارتفاع تصویر در `phase73.css` نیز هم‌راستا شد تا کارت‌های بازار ارتفاع رسانه‌ی ثابت و قابل پیش‌بینی داشته باشند.
