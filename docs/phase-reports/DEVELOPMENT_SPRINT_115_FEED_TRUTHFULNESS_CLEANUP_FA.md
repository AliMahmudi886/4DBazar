# Development Sprint 115 - Feed Truthfulness and Controlled Cleanup

## مسئله

در زمان قطع یا خطای API، build توسعه سه آگهی نمونه را کنار داده واقعی نمایش می‌داد. این رفتار تشخیص خرابی API را دشوار می‌کرد و این تصور را به وجود می‌آورد که فقط سه رکورد در دیتابیس باقی مانده است. بررسی مستقیم مقصد نیز نشان داد endpoint آمادگی API پاسخ `503` می‌دهد؛ بنابراین پاک‌سازی داده به‌تنهایی درمان خطای اتصال نیست.

## تغییرات

- feed وب در صورت پاسخ معتبر API دقیقاً داده سرور را نمایش می‌دهد و دیگر داده نمونه را با آن ادغام نمی‌کند.
- داده نمونه فقط در development و فقط وقتی هیچ منبع واقعی در دسترس نیست استفاده می‌شود؛ build production هنگام خرابی منبع، empty state و هشدار اتصال را نشان می‌دهد.
- خطای query مربوط به feed همراه با stack واقعی در log درخواست API ثبت می‌شود.
- فرمان محافظت‌شده `db:cleanup:market` اضافه شد. اجرای آن فقط با عبارت تأیید صریح مجاز است، وابستگی‌های گزارش/مدیریت/تحلیل را پاک می‌کند و سپس همه محتوای بازار را در یک transaction حذف می‌کند.
- فایل‌های فیزیکی رسانه در این پاک‌سازی نگه داشته می‌شوند تا حذف آگهی موجب حذف غیرقابل‌بازگشت فایل‌ها نشود.

## عملیات مقصد

ابتدا API باید به وضعیت `200` برگردد و از دیتابیس backup گرفته شود. سپس، فقط در صورت تصمیم قطعی برای حذف همه آگهی‌ها:

```bash
source ~/nodevenv/4d-api/20/bin/activate
cd ~/4d-api
MARKET_CLEANUP_CONFIRM=DELETE_ALL_MARKET_CONTENT npm run db:cleanup:market
```

این فرمان کاربران، پروفایل‌ها، دسته‌ها، شهرها، غرفه‌ها و فایل‌های آپلودشده را حذف نمی‌کند.
