# گزارش Development Sprint 106: هم‌ترازی تجربه حمل‌ونقل و داده دمو

## هدف

launcher حمل‌ونقل محلی باید از نظر وزن بصری و مسیر اقدام با launcher ثبت آگهی/خدمت هم‌خوان باشد و جست‌وجوی آن برای کاربر قابل فهم بماند. برای تست واقعی‌تر نیز یک dataset توسعه‌ای بزرگ لازم بود.

## خروجی اجراشده

- کنترل‌های جست‌وجوی حمل‌ونقل در یک پنل پیشرفته‌ی بسته‌شونده قرار گرفتند؛ حالت پیش‌فرض دیگر launcher را بلند و شلوغ نمی‌کند.
- فیلترهای مبدأ، مقصد و نوع مسیر همچنان searchable و انتخابی هستند و جست‌وجوی متنی نیز با Enter یا دکمه اجرا می‌شود.
- badgeهای اضافی از launcher حذف شدند تا ساختار، فاصله‌گذاری و CTAهای آن با launcher ثبت آگهی/خدمت هم‌وزن شود.
- اسکریپت `scripts/seed-demo-data.mjs` اضافه شد و با `npm run db:seed:demo` در محیط توسعه، داده‌ی تکرارپذیر ایجاد می‌کند:
  - ۳۰۰ کاربر تکمیل‌پروفایل‌شده
  - برای هر کاربر یک آگهی، یک خدمت و یک رکورد حمل‌ونقل، در مجموع ۹۰۰ محتوا
  - ۲۴ غرفه برای تست صفحات عمومی و صف بررسی
  - علاقه‌مندی، گفتگو/پیام و تیکت پشتیبانی برای پوشش جریان‌های تعاملی اصلی
  - وضعیت‌های `published` و `submitted` برای پوشش بازار عمومی و moderation
- اسکریپت با `NODE_ENV=production` متوقف می‌شود و رسانه‌ی ساختگی تولید نمی‌کند؛ بنابراین اجرای آن هزینه‌ی object storage ندارد.

## روش اجرای محلی

```powershell
$env:NODE_ENV="development"
npm run db:migrate
npm run db:seed
$env:DEMO_USERS="300"
npm run db:seed:demo
```

اجرای مجدد امن و idempotent است و رکوردهای دمو را با شناسه‌های ثابت به‌روزرسانی می‌کند. داده‌های تعاملی نیز با همان الگو تکرار نمی‌شوند.

## اعتبارسنجی

- `npm run db:seed:demo` موفق: `300 users, 900 contents, 24 storefronts`
- شمارش تعامل‌ها: ۱۲۰ علاقه‌مندی، ۴۰ تیکت پشتیبانی و ۶۰ گفتگو با پیام نمونه
- `npm run check` موفق
- `npm test` موفق: ۵۳ تست API و ۱ تست shared
- `npm run build -- --ignore-scripts` موفق
